規則見 `../../CLAUDE.md`（共通核心）與 `../../types/tool.md`（工具導覽型）。
這份檔案**不部署**：GitHub Pages 的 workflow 在上傳前會 `rm -rf _notes`。

## 反覆出現的錯誤型態

到目前為止（探針階段）出現三型，每一型都不只一次：

1. **把說明文件的節錄當成資料的全部。** 文件站是人寫的導覽，只挑重點講；
   資料庫裡的東西比文件多。凡是「VFB 有 N 套／N 筆」這種句子，都要問 API，不要抄文件。
2. **把「筆數」當成「個數」。** API 回的 `count` 是**列數**。同一個東西會因為
   對位到多套 template、掛在多個類別底下而佔好幾列。
3. **靜默截斷。** API 不回錯誤，只回一個看起來正常的空陣列或短清單。
   凡是翻頁、凡是有上限的地方，都要自己驗「拿到的筆數 ＝ 它說的筆數」。

## 2026-09-13　探針階段

### 1. 「VFB 有四套 template」是錯的，實際上有 10 套
- **錯在哪**：`vfb_plan.docx` 第 3.1 節照文件站 `/docs/concepts/templates/` 寫了四套
  （JRC2018 腦與 VNC、JFRC2、L3 幼蟲、成蟲 VNS）。
- **事實**：`/search?query=*&filter_types=Template` 回 **10 套**。文件沒提到的六套是
  `VFB_00030786`（Ito2014 成蟲腦）、`VFB_00050000`（L1 幼蟲 ssTEM，Cardona/Janelia）、
  `VFB_00101384`（JRC_FlyEM_Hemibrain，hemibrain 自己的 template）、
  `VFB_00110000`（成蟲頭部 McKellar2020）、`VFB_00120000`（成蟲 T1 腿 Kuan2020）、
  以及 JRC2018 的 VNC 版本本來就在清單裡。
- **型態**：第 1 型。

### 2. JFRC2 與 Ito2014 是兩個不同的 template，不是同一個的兩個名字
- **錯在哪**：文件站把它們寫成「JFRC2/Ito2014」，看起來像同一套的別名，計畫書照抄。
- **事實**：`VFB_00017894`（JFRC2，58 個分區，CC-BY-NC-SA 4.0）與
  `VFB_00030786`（Ito2014，75 個分區，CC-BY-SA 4.0）是兩筆，連授權都不同。
- **型態**：第 1 型。

### 3. 知識庫裡的 Template 節點有 20 個，比搜尋看得到的多一倍
- **事實**：Cypher `MATCH (t:Template)` 回 20 個，多出來的十個是 `VFBc_` 開頭的附屬影像
  （每套 template 各一個）。兩個數字都對，答的是不同的問題。
- **本課的裁決**：頁面上講「有幾套 template」一律用**搜尋看得到的 10 套**；
  需要提到 `VFBc_` 時一定寫明那是附屬影像。（共通核心第 2 節：爭議要有裁決。）

### 4. FlyCircuit 的「16,127」是神經元數，但 REST 回的 count 是 68,698
- **錯在哪**：差點把 `run_query?...&query_type=DatasetImages` 的 `count` 當成神經元數寫進教材。
- **事實**：那 68,698 是**列數**。同一顆神經元同時對位到 JFRC2 與 JRC2018U（兩列），
  又同時掛在「adult neuron」與「expression pattern fragment」等類別底下，
  平均一顆佔 4.265 列。真正的顆數要用 Cypher 算：
  `MATCH (i:Individual)-[:has_source]->(:DataSet {short_form:'Chiang2010'}) RETURN count(DISTINCT i)`
  → **16,127**，跟文件站寫的一致。
- **型態**：第 2 型。

### 5. REST 的翻頁到 offset 50,000 就停，而且不報錯
- **錯在哪**：探針第一版把「翻完的列」拿去算不重複 id，得到 11,723，
  差一點就寫成「FlyCircuit 有 11,723 顆」。
- **事實**：`offset=45000` 還回得到 1,000 列，`offset=50000` 開始回**空陣列**，
  沒有任何錯誤訊息。實際翻得到 50,000 列，而 `count` 說有 68,698。
- **怎麼修**：`paged()` 現在回傳 `truncated` 旗標，資料檔裡分成
  `rest_reported_count`／`rest_rows_fetched`／`rest_truncated` 三個欄位，
  顆數改用 Cypher 算。
- **型態**：第 3 型。**這一條要寫進教材**——它是「為什麼要學 API 那一層」最好的例子。

### 6. 連線資料集的版本跟文件寫的不一樣，而且新舊版同時在庫裡
- **事實**：`/list_connectome_datasets` 現在回 8 套，BANC 是 **v888**（文件寫 v626）。
  Cypher 算每套的神經元數時，**兩版都在**：`Bates2025` = BANC v626（80,003 顆）、
  `Bates2026` = BANC v888（64,546 顆）；hemibrain 也是 `Xu2020Neurons` v1.0.1 與
  `Xu2020NeuronsV1point2point1` v1.2.1 兩列；male CNS 是 `Berg2025` v0.9 與 `Berg2025a` v1.0。
- **意義**：這不只是「不能把重疊組織的資料集相加」，**連同一套資料的新舊版也不能相加**。
  PART 4 要拿這張表當例子。
- **型態**：第 1 型。

### 7. 文件提到的 FANC 不在連線資料集清單裡
- **事實**：`/docs/data/em/` 列了 FANC（CATMAID，成蟲雌性 VNS），
  但 `/list_connectome_datasets` 只有 `catmaid_fafb` 與 `catmaid_l1em`。
- **還沒查清楚**：是被移除了，還是它不算「connectome dataset」而只有骨架。
  **寫 PART 4 之前要查**，不要在頁面上出現「VFB 有 FANC」這種沒驗過的句子。

### 8. 授權是逐筆的，而且有一套是 NC（禁止商業使用）
- **事實**（都從 `get_term_info` 的 `Licenses` 欄讀出來）：
  JRC2018 系列（腦、VNC）與 JFRC2 是 **CC-BY-NC-SA 4.0**；
  Ito2014、Wood2018、Court2018、McKellar2020 是 CC-BY-SA 4.0；
  hemibrain template 與 Kuan2020 是 CC-BY 4.0；
  FlyCircuit 是自訂的 **FlyCircuit License**（不是任何一種 CC）。
- **意義**：`types/tool.md` 那條「逐筆查授權」在第一次抓資料就驗證了。
  本課是非營利教學，NC 沒有問題，但**圖說要寫出是哪一種**，
  而且 FlyCircuit 那套要照 VFB 的要求引 Chiang 2010。

## 探針本身的兩個設計決定（寫下來以免日後又改回去）

- **資料檔裡不放時間戳。** 抓取時間、耗時、雜湊全部放 `out/_manifest.json`。
  否則 VFB 換版後重跑，`diff` 會把每一個檔案都標成「改了」，真正的變動反而看不見。
- **`/status` 只留 health 與 upstream，丟掉快取與連線計數。**
  那些數字每秒都在動，留著會讓每一次重跑都報「service 內容變了」，
  把第一項的變動偵測變成雜訊。（第一版就是這樣，跑兩次才發現。）

## 2026-09-13　PART 1

### 9. 「分區數＝清單筆數減一」這條規則，十套裡有兩套是錯的
- **錯在哪**：`get_term_info` 的 `Domains` 欄第一格（index 0）通常是 template 自己，
  所以第一版探針寫成 `len(Domains) - 1`。
- **事實**：`VFB_00101384`（hemibrain template）與 `VFB_00120000`（成蟲前足）
  **根本沒有那一格**，減一就少算一個。正確的數字是 97 與 4，不是 96 與 3。
- **怎麼抓到的**：同一個數字用兩種算法各算一次——一種數清單、一種直接跑
  站上的 `PaintedDomains` 查詢——然後比對。兩個算法一致才寫進教材。
  **不是眼睛看出來的，是程式比出來的。**
- **教訓**：「位置」不能拿來當身分。要排除某一筆，就比對它的 id，不要假設它排在第一個。
- **型態**：第 3 型的變形——資料結構不一致，而且不會報錯。

### 10. 頁面上的英文引文，有一條是改寫過的
- **錯在哪**：頁面上寫成
  「The only way to put a FlyWire neuron next to a split-GAL4 expression pattern is to bridge between them.」
  這句讀起來完全通順，也確實在說明文件講的意思範圍內。
- **事實**：原文是一個更長的句子，前面還有
  「Data on VFB arrives registered to whichever standard its producers used — JRC2018 unisex, ... —
  and the only way to put a FlyWire neuron ...」。
  頁面上那個大寫的 The 是摘要過程加上去的，原文沒有這個句子。
- **另外三條**是相反的問題：引到一半就補上句點，而原文還沒結束
  （`is the standard.` 原文是 `is the standard — which looks broadly the same...`；
  `you need EM.` 原文是 `you need EM (connectivity data).`）。
- **怎麼抓到的**：新寫的 `scripts/quote_audit.py`，把每一條 `<p lang="en">`
  逐字對回說明文件的純文字。**四條全部是程式抓到的，人看不出來。**
- **稽核程式本身踩了兩個坑**（跟共通規範第 3 節列的是同一類）：
  1. 剝標籤之後句末的句點會變成「template .」，不先把標點前的空白去掉，
     四條真引文會全部被誤判成對不到。
  2. 引文中間用 `…` 標省略，但正規化用的 NFKC 會把 `…` 轉成三個句點，
     所以**要先按 `…` 切段，再正規化**。
- **型態**：新的一型——**改寫過的引文讀起來比原文通順**，所以特別難發現。

### 11. 側視圖不先把左半腦拿掉，等於只畫了一片視葉
- **錯在哪**：第一版的側視圖從左側看整顆腦，結果最靠近攝影機的左視葉把其他全部擋住，
  34 個分區裡只看得見 30 個，而且都是同一片。
- **怎麼修**：先裁掉左半腦（中線由兩片視葉質心的中點定），再從中線往外看。
- **型態**：共通規範第 7 節那條「攝影機站在軸的哪一端決定哪一面擋住哪一面」的實例。

### 12. REST 回的授權欄位是不穩定的，同一個 id 問五次會給兩種答案
- **錯在哪**：PART 1 那張 template 表的授權欄，第一版照 `get_term_info` 的
  `Licenses` 欄抄。十套裡有四套抄錯（Ito2014、Wood2018、Court2018、McKellar2020
  都被寫成 CC-BY-SA 4.0，實際是 CC-BY 4.0），`VFB_00050000` 還被寫成兩種授權。
- **事實**：同一個 id 連問五次，`VFB_00110000` 回過三次 `CC-BY_4.0`、
  兩次 `CC-BY-SA_4.0`。**不是我抄錯，是那一欄本身會變。**
- **怎麼判定哪個對**：改問知識庫——
  `MATCH (t:Template)-[*1..2]-(l:License) RETURN t.short_form, collect(DISTINCT l.label)`
  每一套 template 都只連到**一個** License 節點，連問三次結果都一樣。
  授權實際掛在 template 影像來源的那個 dataset 上（`has_source` → `has_license`）。
- **怎麼修**：探針的授權改從知識庫取，REST 那一欄照樣存下來當對照，
  兩邊不同就在 note 裡列出來。頁面上加一個方框告訴讀者「看到不一樣以表為準」，
  並指出最終依據是原始論文的授權聲明。
- **型態**：第 3 型（靜默不一致）的極端版——**連重跑同一個查詢都會得到不同答案**。
  這條也是 `types/tool.md` 那句「授權是逐筆掛在資料上的」的下一層：
  逐筆還不夠，還要問對地方。
- **順帶的好消息**：釐清之後，答案反而更好記——
  **只有 JRC2018 那一家（腦、VNC）與 JFRC2 帶 NC，其餘七套都是 CC-BY 4.0。**

### 13. 兩個交叉檢查都是「多做一次」換來的
第 9 條與第 12 條有同一個形狀：**同一個數字用兩條路各取一次，然後比對。**
分區數（數清單 vs 跑查詢）抓到兩套算錯；授權（REST vs 知識庫）抓到四套抄錯。
兩次都不是看出來的，是比出來的。**這件事要變成這個專題的預設做法**——
凡是要寫進教材的數字，先問「有沒有第二條路可以問到同一個數字」。

## 2026-09-14　PART 1 回頭修

### 14. 授權方框「以這張表為準」跟「最終依據是原始論文」互相打架
- **錯在哪**：第 3 節那個方框原本寫「如果你在網站上看到的授權跟這張表不一樣，**以這張表為準**」，
  結尾又寫「真要用在正式場合的話，回頭查那套 template 原始論文的授權聲明，那才是最終依據」。
  使用者指出：**如果最終都要回頭查，那憑什麼叫讀者以這張表為準。**
- **問題的形狀**：一個方框同時回答了兩個不同的問題，而兩個答案的層級不同——
  1. 「VFB 的兩個介面給我不同答案，該信哪一個？」→ 知識庫（我們有證據：面板重問會變、知識庫重問一致）。
  2. 「我能不能拿這套 template 來用？」→ 原始釋出者。VFB 兩邊都只是**轉錄**。
  第 12 條查清楚的是第一個問題，寫的時候卻用「為準」這個帶裁決意味的詞把它講成了第二個問題的答案。
- **怎麼修**：把方框拆成兩段。第一段只說「這張表記的是知識庫那一個，看到兩邊不一樣不是你看錯」；
  第二段明講「這張表回答的是 VFB 記了什麼，不是你可以做什麼」，並把表的定位寫成
  **索引（該去查哪一套、大概會查到什麼），不是依據**。第 143 行「這一欄要先看」一併改掉，
  免得它又把讀者留在那一欄。
- **教訓**：**「以 X 為準」這句話要先問「為準是為了回答哪個問題」。**
  我們對某個欄位做了交叉驗證，得到的是「這兩個來源哪個可信」，不是「這個數字有權威」。
  往後凡是要寫「以…為準」，先確認裁決的範圍沒有超出證據的範圍。
- **型態**：新的一型——**證據的範圍與句子的範圍對不上**。跟前面十三條不同，
  這一條不是資料錯，四道稽核也抓不到（數字全對、引文全對、標籤全平衡）。
  是使用者讀出來的。

### 15. 作業單第 1 步照著做會卡住：搜尋結果裡根本沒有那個編號
- **錯在哪**：第 7 節作業單原本寫「在搜尋框輸入 `JRC2018Unisex`，點進結果。
  資訊面板（Term Info）裡會出現它的編號 VFB_00101567」。
  使用者實際去操作，回報「輸入完之後就會出現很多項，但就是沒有 VFB_00101567」。
- **實測結果**（`scripts/vfb_probe.py` 新增的 `worksheet` 探針，2026-09-14）：
  這一句話裡有**三個各自獨立的坑**，任何一個都足以讓學員卡死。

  1. **編號不在結果清單裡。** 搜尋回的每一列只有名字，編號要點進去之後才在
     Term Info 與網址列出現。原句「輸入…點進結果。資訊面板裡會出現編號」
     語法上沒錯，但讀起來像是「輸入完就看得到編號」——
     學員因此在清單裡找編號，永遠找不到，也就走不到「點進去」那一步。
  2. **回來的 103 筆裡有 99 筆不是 template。** 名字全長成
     「bulb on JRC2018Unisex adult brain」「medulla on JRC2018Unisex adult brain」。
     原因很單純：畫在一套 template 上的每一塊，名字裡都帶著那套 template 的名字，
     所以搜尋 template 的名字會把它的整份分區地圖一起撈回來（JFRC2 是 129 筆裡 127 筆）。
     **這裡我自己先錯了一次**：第一版探針照「型別是不是 Synaptic_neuropil」分類，得到 97，
     就把 97 寫進頁面說「97 筆的名字長成某某 on …」。但顎神經節的型別是 `Ganglion`
     而不是 `Synaptic_neuropil`，名字卻一樣帶「on …」——**照型別分出來的數字，
     拿去描述學員在畫面上看到的名字，本來就對不上**。改成照名字分（99），
     並加一條 `all_rows_accounted_for` 檢查：分類完的各群要加得回總數，加不回就是還有沒想到的東西。
  2b. **搜尋 JRC2018Unisex 會連另一套 template 一起撈回來。** 剩下的 4 筆不是 2 筆：
     2 筆是 VFB_00101567（你要的），另外 2 筆是 **VFB_00200000 JRC2018Unisex<u>VNC</u>**

第 1 步原本寫「面板上寫的是 **JRC2018U**，不是你以為的 JRC2018Unisex」。查了才知道，
`get_term_info` 有**兩個**名字欄位：`Meta.Name`＝`[JRC2018Unisex](VFB_00101567)`（面板的 Name 欄顯示這個）、
頂層 `Name`＝`JRC2018U`（**查詢的標籤用的是這個**，所以那支查詢叫 "Painted domains for JRC2018U"）。
v3 前端的程式碼取的是 `Meta.Name`。**所以面板上寫的其實是 JRC2018Unisex，我寫反了。**
改成講清楚「同一個東西在同一個面板上有兩個名字」，順便把第 2 步那個查詢名字的來歷交代掉。

- **欄位名的出處**：`Aligned to` 來自 v2 `main.bundle.js` 裡的註解
  （`// Raw-id link (e.g. "Aligned to" template short_form)`）與 v3 的
  `$r.push({key:"Aligned To", ..., isAlignedTo:!0})`——**兩個版本大小寫不同**，頁面上註明了。
  其餘欄位名對照 `/docs/website-features/terminfo/` 與 `get_term_info` 的回傳鍵。
- **探針**：worksheet 加 `term_info_fields_pointed_at`，
  把作業單指名的每一欄的**現值**存下來（Name／短名／兩支查詢標籤／Aligned to 列出的編號／
  Licenses／來源資料集）。**欄位改名或內容變了，重跑時 diff 會叫出來**——
  因為這幾欄一變，學員就會照著找不到。
- **型態**：第 15～18 那一串的延伸，但角度不同。前面四條是「起點錯」「數字錯」；
  這一條是**指令不完整**——每一句都對，但學員拿著它到畫面前找不到東西。
  作業單的句子要同時回答三件事：**去哪裡看、看什麼、看到什麼算對。**
  原本的第 4 步三件只答了中間那一件。
