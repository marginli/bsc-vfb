1這個網站不是只能用滑鼠

PART 3 用滑鼠做出了一份清單：medulla 裡有一部分在裡面的神經元，471 種。那份清單還有兩種拿法：寫三行 Python，或者直接用中文問 AI——而 VFB 自己就架了一台伺服器，專門讓 AI 去問它。

這一部分要換掉的觀念：「這個網站只能用滑鼠。」三種做法問的是同一個資料庫，但它們的預設值不一樣——所以會給出不一樣的數字。第 5 節把三個數字擺在一起，逐項解釋差在哪裡。那一節才是這一部分真正要教的東西；前面三節只是把工具介紹完。

471 這個數字出自 PART 3 第 2 節（out/query_overlaps.json，scripts/vfb_probe.py，2026-09-14）；第 5 節會把三層各自問到的數字並排。

前五個部分都不用安裝任何東西，這一部分不是。滑鼠那一層仍然在瀏覽器裡做得完；程式與 AI 兩層要裝東西。不想裝也沒關係——第 5 節的結論不需要你自己跑過就看得懂。

2滑鼠這一層，以及它的天花板

前五個部分做的每一件事，都是滑鼠這一層：PART 1 比對兩套標準腦的分區、PART 3 做出那份 471 種的清單並把它帶走（三種下載都在那一節）、PART 5 跑一次 NBLAST 再把骨架下載下來。這一層能做的事比多數人以為的多。

但它有三件做不到的事，而且每一件都會在真的研究裡撞上：

做不到什麼時候會撞上
批次你要的不是一個腦區，是五十個
算不重複的個數畫面給的是列數，而列數不是個數——要去重就得自己拿全部的編號回來
把結果接到下一步清單拿到了，但下一步要拿它去問別的問題、或餵進自己的分析

這三件事就是接下來兩層存在的理由。底下兩節先各自介紹，第 5 節再把三層擺在一起比。

471 這個數字出自 PART 3 第 2 節（out/query_overlaps.json，scripts/vfb_probe.py，2026-09-14）。第 5 節會把三層各自問到的數字並排。

3程式：vfb-connect

VFB 官方的 Python 套件。裝一行：

pip install vfb-connect

本課實測的是 2.4.5 版。用起來是三行：

from vfb_connect import VfbConnect
vc = VfbConnect()
vc.get_terms_by_region('medulla')
兩件文件沒寫、但你一定會遇到的事。
一、import 本身就會連線。光是把套件匯入並建立 VfbConnect()，就要五秒，而且會印出六百多個字元的彩色橫幅。寫進腳本裡會很吵，要自己把輸出關掉。
二、回傳的是 DataFrame，不是 list 或 dict。所以拿到之後是用 len()、.columns、['id'] 這一套，不是 for x in ... 逐筆挑鍵。

版本、耗時、橫幅長度與回傳型別，由 scripts/three_layers.py 在 2026-09-14 實際跑一次量得，記在 out/three_layers.json 的 code 底下。

4AI：VFB 自己架的 MCP 伺服器

MCP（Model Context Protocol）是一套讓 AI 助理去呼叫外部工具的協定——這個詞本課第一次用，意思就是：有人把一組工具包好、放在一個網址上，AI 助理連上去就能用。VFB 自己架了一台：

https://vfb3-mcp.virtualflybrain.org

不需要認證、不需要 API key。本課實測到的伺服器版本是 vfb3-mcp-server 1.11.2。以 Claude Code 為例，接上去是一行：

claude mcp add --transport http virtual-fly-brain \
       https://vfb3-mcp.virtualflybrain.org

接上之後，你就可以用中文問「medulla 裡有哪些神經元」，AI 會自己挑工具、自己填參數。

它開出來的工具有 11 個

VFB 的說明文件介紹了七類。實際連上去問它，回來的是 11 個——七類都在，另外四個文件沒提，而且那四個全都跟 PART 4 的主題有關：

工具名做什麼文件有提嗎
get_term_info查一個詞的全部資訊有
search_terms搜尋詞條有
run_query跑現成查詢（含 NBLAST）有
get_hierarchy階層瀏覽有
list_search_facets列出可以用來篩的類別有
resolve_entity把名字解析成編號有
resolve_combination解析 split-GAL4 組合名有
list_connectome_datasets列出連線資料集沒有
query_connectivity跨所有連線資料集查連線沒有
get_predicted_neurotransmitters查預測的神經傳導物質沒有
get_known_neurotransmitters查已知（人工整理）的神經傳導物質沒有
「文件是導覽，不是實作」——這是本課第五次遇到。前面四次分別是：template 文件寫四套實際十套（PART 1）、文件的搜尋參數跟前端實際送的不一樣（PART 2）、結果表的欄名跟程式介面的鍵名不同（PART 3）、以及連線資料集清單只收八套而知識庫裡有六十套（PART 4）。要知道一個服務真的提供什麼，去問它，不要讀它的介紹。

伺服器版本、11 個工具的名稱與參數，由 scripts/three_layers.py 走 MCP 的握手流程後取得（2026-09-14），記在 out/three_layers.json 的 ai 底下。

5同一個問題，三種做法

現在把三層擺在一起。問題就是 PART 3 那個：medulla 裡有一部分在裡面的神經元，有幾種？

471
滑鼠：結果表的標題
471
AI：MCP 的 run_query
510
程式：get_terms_by_region()

滑鼠與 AI 一致，程式那一層多了 39。差在哪裡？把兩邊的編號取回來逐一比對，答案很單純：

差別多出來的是什麼為什麼
510 → 48139 個次分區：outer medulla、medulla layer M1–M10、inner medulla⋯函式叫 get_terms_by_region，它回的是「跟這個腦區有關的所有詞」，不是只有神經元。加上 cells_only=True 就排掉了
481 → 4719 個膠細胞 ＋ 2 個神經元（Dm8a、Dm8b）cell 不等於 neuron——膠細胞也是細胞。那兩個神經元見下一段
反過來，471 裡有 1 個是程式那層沒有的FBbt_00110069，標籤是 obsolete distal medullary amacrine neuron Dm8b一個已棄用的詞。vfb-connect 預設 include_deprecated=False 會把它排掉，而站上那支查詢沒有這個預設

最後那一列值得多看一眼：站上那 471 種裡，有一種是已經棄用的詞，而它的新版（FBbt_00053638 與 FBbt_00053639，Dm8a 與 Dm8b）反而只出現在程式那一層。同一個名字、兩個編號，一個作廢一個現行——這正是 PART 4 第 4 節講的棄用，出現在詞的層次上。

三個差別，全部來自參數的預設值。沒有一個是哪一層算錯了。所以規矩是：報告一個數字的時候，要連「你用的是哪一層、那一層的預設值是什麼」一起說。PART 4 第 6 節那份清單要再加一件：你用的是哪一層。

三層的數字、逐項差集與每一個差異項的標籤，由 scripts/three_layers.py 在 2026-09-14 各跑一次取得，原始輸出在 out/three_layers.json（滑鼠那一層的數字讀自 out/ui/query_results.json，也就是真的瀏覽器拍下來的標題列）。

6哪一層該用在什麼時候

這一層什麼時候用要付的代價
滑鼠看一顆、確認一件事、把東西打包帶走。預設就用這一層做不了批次；筆數是介面的性質（PART 2 第 5 節）
程式要批次、要算不重複的個數、要把結果接到下一步要裝、要五秒的啟動、而且要自己弄清楚每個參數的預設值
AI你還不知道該用哪一支查詢的時候；或者問題不好翻成介面操作它會替你挑工具、填參數——而那些正是你該自己決定的事
AI 那一層有一個特有的風險：它會替你做決定，而且不會告訴你。上面那三個差別——次分區算不算、膠細胞算不算、棄用的詞算不算——每一個都是有人替你決定了。用滑鼠時決定的人是 VFB，用程式時是那個函式的預設值，用 AI 時是 AI。三種都不是你。
所以問完之後要追一句：「你用了哪一個工具、填了哪些參數？」——MCP 的回應裡有這些資訊，而那是你把它的答案寫進論文之前必須看的東西。

7動手做

三步，都要裝東西——前五個部分的作業單都不用，只有這一份要。不想裝也可以只讀不做：第 5 節的結論不需要你自己跑過就看得懂。

  1. 用程式問一次。裝好之後跑第 3 節那三行： 
    pip install vfb-connect
    from vfb_connect import VfbConnect
vc = VfbConnect()
vc.get_terms_by_region('medulla')
    看到什麼算對：回來的是一個 DataFrame。先不要看內容，先看 len()——是 510。
    而你在 PART 3 用滑鼠得到的是 471。先停在這裡想一下為什麼。
  2. 加一個參數再問一次。
    vc.get_terms_by_region('medulla', cells_only=True)
    看到什麼算對：481。
    兩個數字都不是 471，而你一個字都沒改問題，只改了參數。第 5 節那張表逐項解釋那 39 個與那 10 個各是什麼。
  3. 接上 MCP，然後追問它。照第 4 節那一行把伺服器加進你的 AI 助理，用中文問：「medulla 裡有一部分在裡面的神經元有幾種？」
    看到什麼算對：它應該回你 471。
    然後追問一句：「你用了哪一個工具、填了哪些參數？」把它的回答跟第 5 節那張表對一遍。
    這一步才是這份作業單的重點：不是讓 AI 給你答案，是讓它交代它怎麼得到那個答案的——因為那三個預設值，它一個都不會主動告訴你。

三步的每一個數字，由 scripts/three_layers.py 在 2026-09-14 各跑一次取得，原始輸出在 out/three_layers.json。

這是這門課的最後一個部分。六個部分走完，你手上有的不是一套操作步驟，而是一組習慣：先問這個數字在回答什麼問題、先確認自己在哪一個網站上、先看它是哪一套資料的哪一版、先問有沒有第二條路可以問到同一個數字。
這些習慣不會因為 VFB 改版而失效——而這門課裡所有會失效的東西，都標了日期。
